# SE104 reference/node observer

Version0.3.0-se104 targets only SkyrimSE1.7.104.0 with SKSE2.3.1 and the matching
Address Library13. Its modern metadata and Query/Load paths require that exact
runtime; Load checks it before SKSE::Init. This is a separate CMake build option,
not the VR DLL renamed for SE. Default builds still select the original VR target.

The SE subset implements inspect kind=world_observer through DevBench's existing
extension ABI. Reference/node snapshots run in one bounded SKSE main-thread task,
with sessionId, loadGeneration, sampleId, actual reference handle/FormID,
deleted/disabled/loaded3D and typed scene/node transforms. There are no borrowed
VR offsets, rig pointers, input commands or guessed frame relocations.
producerFrame is explicitly null. Physics, rendered pixels, VR picking and actor
inventory state are unsupported; requests for these domains are rejected. Native
invalid text is replaced with textEncodingLossy:true and quality:partial, rather
than escaping the C ABI as a JSON exception. Replacement is not exact text proof.

Cancelled/expired/stale work is refused before engine reads. Initial generation
can be established only after main-thread admission from an actual loaded player,
attached cell and clear startup/menu state; it cannot recover a failed load.
Load-generation changes reject stale work. Deadlines remain absolute; already
started reads may finish after a client timeout and are not reported as success.
This is sampled identity/state, not a physics/render freeze or a mod-test oracle.

## Reacquire the modern SDK outside Git

Use se-dependencies.json for exact owner-fork/source/submodule pins. No external
SDK, downloaded header, package, program, DLL, PDB, save or token is stored in this
repository. Build into an external directory, not any Git checkout.

1. Acquire Visual Studio x64 C++ tools, CMake>=3.24, Python3.11+, Git and Xmake3.1.1.
   The modern DevBench acquisition recipe is in the separate skyrim-autotest
   repository at docs/devbench-modern-se.md. Its pinned DevBench source3bb1673
   selects modern CommonLib0c95630 and OpenVR60eb187. Clone externally, initialize
   submodules and verify these exact commits before compiling.
2. Configure that external modern SDK with the exact sdkBuildFeatures from
   se-dependencies.json. Build the actual commonlibsse-ng target; never rename an
   unrelated legacy .lib. Retain Xmake package lock/target output and compiler
   versions externally. The observed package versions are recorded separately;
   resolve exact packages, not whatever newest packages happen to be installed.
3. Create an external SDK manifest with schemaVersion1, source:{path,commit},
   openvr:{path,commit}, library:{path,sha256}, includeDirs:[absolute package
   include directories], linkLibraries:[{path,sha256}]. The actual target's
   `xmake show -t commonlibsse-ng` provides include/link settings. Use the actual
   commonlibsse-ng.lib plus matching spdlog.lib and DirectXTK.lib. OpenVR must be
   the SDK's actual extern/openvr submodule. The builder adds and hashes the SDK
   source include directory and OpenVR headers as well as every supplied package
   header. Generated public headers and libraries are checked before/after build.
4. Run the following from this checkout, supplying your external SDK manifest:

```powershell
python tools/build_se.py --build-dir C:/TestBuilds/observer-se104 --sdk-manifest C:/TestBuilds/modern-sdk/sdk-manifest.json
```

The builder fetches the three exact hash-checked DevBench integration files into
build/external/, configures OBSERVER_BUILD_SE104=ON, builds the DLL and its
matching PDB, and executes CTest. manifest.json retains actual source/SDK/header/
library/ABI/output hashes and configure arguments. It never installs, launches or
sets a qualified flag. A source build cannot establish actual game compatibility.

## Operator preparation and actual qualification

Only Polygon owns installed test providers and the exact platform attempt in this
project. Give it the external manifest and DLL/PDB, not a guessed version label.
Use the existing prospective standard preparation barrier and preserve original
MO2 profile/configuration; install into a separate isolated SE tool mod or use
the executor's pinned staging/restore mechanism. Never overwrite a personal mod.
Do not add tool hashes to a schema2 subject order.

A tool qualification must discover the actual extension, verify its declared
read-only/schema/bounds, capture real player identity and loaded3D, compare a
second sample's session/generation/handle, exercise typed Papyrus observations
and verify clean shutdown/restoration/archive. Actor-base and SKEE readback
remain separate consumers of this data. Their actual APIs, required array
transport and mod composition need their own assertions; the observer does not
provide RaceMenu/SKEE itself. Save/load continuity, rendered geometry and subject
mod correctness are not established by an identity probe.

Compilation/offline tests alone leave nativeQualified:false. Retain actual game
qualification evidence separately and state precisely which domains it covers.
